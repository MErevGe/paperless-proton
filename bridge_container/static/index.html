SSL / TLS

Trust the Bridge certificate

Download the public certificate and copy it to your Paperless Compose directory.

↓ Download certificate

Add these entries to your existing Paperless service, then recreate it: 

environment:
  PAPERLESS_EMAIL_CERTIFICATE_LOCATION: /etc/paperless/proton-bridge-ca.crt
  PAPERLESS_EMAIL_ALLOW_INTERNAL_HOSTS: "true"
volumes:
  - ./proton-bridge-ca.crt:/etc/paperless/proton-bridge-ca.crt:ro

Give a separate mail worker the same certificate and setting. Keep certificate verification enabled.

STEP 03

Your import profiles

Give each Proton account its own Paperless user, API token and folders.

Paperless connection

No API token saved.

Use the token of the Paperless user who should own these documents. That user needs permission to view, add and change mail accounts and mail rules. The field clears after a successful save. Leave it blank to keep this profile's saved token.

Paperless superusers can access all documents. Existing Paperless workflows and sharing rules can also grant access.

Connection options

HTTP exposes the API token and Bridge password on the network. Prefer HTTPS.

Only needed if Paperless uses a private certificate authority. Server verification stays enabled.

Import rule

Create the source and destination folders in Proton Mail first.

Choose a connected email address to load its folders.

Use 0 to 32767 days. Set 0 to include email of any age. Moving an old email into the source folder does not make it newer.

Paperless imports matching attachments and moves the processed email. The rule is enabled when you apply it.
